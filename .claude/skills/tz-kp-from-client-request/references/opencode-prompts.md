# Сборка MVP итерациями и хранение материалов

После согласования ТЗ и КП работа идёт цепочками коротких промптов, а не одним большим запросом. Один промпт = одна задача. Меняется сценарий — сначала обновляем ТЗ, потом продолжаем.

## Четыре этапа цикла

1. **Анализ ТЗ** — разобрать задание, задать критические вопросы, предложить структуру файлов. Разработку не начинать.
2. **Build** — собрать только согласованные сценарии и тестовые данные.
3. **Верификация** — пройти критерии приёмки и крайние случаи.
4. **Refine** — исправить один приоритетный дефект, не расширяя скоуп.

Правило одного дефекта за итерацию не про аккуратность, а про сохранность: пакет правок разом ломает то, что уже работало, и найти причину становится дороже.

## Структура промпта на MVP

Контекст → проблема → пользователь → сценарий → запрос на MVP (формат, 3–5 функций) → ограничения → данные. В конце — просьба сначала предложить план файлов и только после подтверждения реализовывать.

Реальные данные клиента в промпты не попадают: они уходят в модель. Только тестовые или обезличенные.

## Обезличивание исходников

Правило «реальные данные в промпты не попадают» действует и до MVP: на шаге анализа в модель уходят переписка, брифы и расшифровки созвонов.

- Заменить имена, телефоны, почту, ИНН и реквизиты на метки (`[КЛИЕНТ]`, `[ТЕЛЕФОН]`, `[КОНТАКТ-1]`)
- Таблицу соответствий метка → реальное значение хранить отдельно, вне папки проекта
- Коммерческие подробности (цены, договоры, объёмы), которые клиент просил не разглашать, убрать или обобщить
- Файлы для анализа класть в `00_исходники/` только после этой проверки

## Готовые промпты

**Анализ материалов заказчика:**
```
Изучи файлы в этой папке и напиши отчёт: какая информация по проекту есть,
чего не хватает, где источники противоречат друг другу.
```

**Формирование ТЗ:**
```
Ты — специалист по формированию технического задания.
Приоритет источников: только файлы этой папки, в интернет не ходи.
При противоречиях используй источник с более высоким приоритетом и фиксируй
решение как допущение или риск. Не добавляй функции, которые клиент не просил.
Составь одностраничное ТЗ из девяти блоков: контекст, проблема, аудитория,
сценарий, требования, ограничения, критерии приёмки, допущения и риски,
что нужно от заказчика. Помечай [факт] / [допущение] / [гипотеза].
Статус документа: черновик, внутренний.
Разработку не начинай до моей команды.
```

**Старт разработки:**
```
Начинай реализацию MVP по утверждённому ТЗ. Работай итерациями: сначала
перечисляй, что будешь изменять, затем реализуй. Не изменяй лишние файлы,
не добавляй функции вне ТЗ. Ориентируйся на бизнес-правила, делай понятные
сообщения об ошибках. Первая итерация: каркас приложения, визуальные токены,
формы, модели данных. Когда итерация принята — переходи к следующей.
Когда весь функционал из ТЗ добавлен, сообщи об этом.
```

**Верификация:**
```
Проверь MVP по критериям приёмки из ТЗ и по крайним случаям: пустые поля,
некорректные данные, перезагрузка страницы. Выведи результат по каждому
критерию отдельно. Затем исправь один самый приоритетный дефект,
не расширяя скоуп.
```

## Хранение материалов

Проект живёт в структуре, которая переживает передачу другому человеку:

```
<проект>/
├── 00_исходники/     переписка, интервью, бриф клиента
├── 01_ТЗ/            ТЗ с версиями
├── 02_КП/            КП, расчёт трудоёмкости
├── 03_промпты/       история промптов по итерациям
└── 04_MVP/           код и скриншоты
```

Для базы знаний (Yonote, Notion и аналоги) подключение через MCP: создать API-токен, включить MCP-сервер, прописать адрес и токен в конфиг, перезапустить агент и проверить подключение. Токен не публиковать и не класть в репозиторий и скриншоты. MCP подключается к выбранной папке — для другого проекта настраивается отдельно.

Пример конфига:
```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "knowledge-base": {
      "type": "remote",
      "url": "<адрес MCP-сервера>",
      "enabled": true,
      "headers": { "Authorization": "Bearer <ключ API>" }
    }
  }
}
```

Промпт на перенос:
```
Оформи проект из этой папки на странице в базе знаний. Добавь исходные данные,
ТЗ, КП, историю промптов по итерациям, таблицу критериев приёмки с результатами
проверки и ретроспективу. Используй заголовки, callout-блоки и таблицы.
```

Накопленные ТЗ, КП и промпты — это не архив, а заготовки: следующий похожий проект собирается из них в разы быстрее, а показать их можно как портфолио.
