# Лендинг ТРЛ: маркировка «Честный знак»

Одностраничный лендинг для ООО «Технические решения логистики» (Казань) — услуги маркировки товаров «Честный знак» на собственном таможенном складе. Стек — чистый HTML/CSS/JS, без сборки и зависимостей.

**Главный источник требований — `TZ_landing_markirovka.md`** (ТЗ v1.3): раздел 5 «Требования», «Критерии приёмки», приложение А (контакты и текст FAQ от заказчика). Любая правка сверяется с ним; расхождения — вопрос пользователю, а не молчаливая правка.

## Структура

Кода пока нет — при создании придерживаться этой схемы (по образцу статического лендинга без сборки):

```
index.html    — единственная точка входа, вся разметка и CSS/JS inline
assets/       — фото склада (копии из «Материалы заказчика/Фото склада/», подготовленные к вебу)
docs/         — отчёты статуса, Lighthouse-отчёты (нейминг: YYYY-MM-DD — тема — тип.md)
```

## Локальный запуск

Зависимостей нет. Два варианта.

**Просто открыть файл** — двойной клик `index.html`. Работает без сервера.

**Через локальный сервер** (нужно для теста на телефоне / Lighthouse / Playwright):

```bash
py -m http.server 8000
# затем http://127.0.0.1:8000/
```

## Внесение изменений

### Что нельзя менять без заказчика

Зафиксировано в ТЗ (раздел 5 и «Допущения и риски»):

- заголовок hero «ТАМОЖЕННЫЙ СКЛАД В КАЗАНИ!» — формулировка и регистр;
- порядок услуг: алкоголь + лицензия РАР — первым;
- текст FAQ — 12 вопросов-ответов приложения А;
- каналы заявок — только email + MAX; Telegram и WhatsApp вне скоупа;
- позиционирование: крупно «Казань», точный адрес (Зеленодольский район) — мельче, расхождение не скрывать;
- упоминание лицензии РАР — пока без номера (реквизиты заказчик пришлёт позже).

### Форма заявки — рабочая, но тестируем на заглушках

В отличие от макетных форм, здесь форма должна реально отправлять заявки на email и в MAX-бота заказчика. При тестировании использовать только тестовые данные (имена/телефоны-заглушки) — реальные заявки заказчика не засылать. Интеграции email/MAX подключать по ТЗ п.5 (функциональные требования 10) и разделу «Данные».

### Адаптив

Мобильная адаптация в приоритете — основной трафик идёт с телефонов (реклама Яндекса). Менять адаптив — в медиа-запросах внизу `<style>`. Проверка: первый экран читаем без горизонтальной прокрутки, кнопки «Позвонить» и «Заказать звонок» видны без прокрутки.

### SEO

Ключевые запросы (ТЗ п.5): «маркировка честный знак», «таможенный склад Казань» — основные; «маркировка товаров Казань», «маркировка импорта», «ИМ-70», «маркировка продуктов питания на таможенном складе», «маркировка алкоголя Честным знаком» — дополнительные. `<html lang="ru">`, мета-теги на русском, Яндекс.Метрика + цель «отправка формы».

## Проверка ошибок

### 1. Консоль браузера (минимум)

Открыть `http://127.0.0.1:8000/` в Chromium → DevTools → Console. Ожидается: пусто. 404 на `assets/*`, JS-исключения — блокеры.

### 2. Playwright (если доступен)

Прогнать страницу через Playwright MCP, собрать ошибки консоли и падения сети. Критично: отсутствие 4xx/5xx и JS-исключений.

### 3. Lighthouse

`py -m http.server 8000` → DevTools → Lighthouse → Navigation → Mobile → Analyze.

| Категория | Минимум |
|---|---|
| Performance | ≥ 90 |
| Accessibility | ≥ 95 |
| Best Practices | ≥ 90 |
| SEO | ≥ 90 |

### 4. Критерии приёмки из ТЗ

Полный чек — таблица «Критерии приёмки» в `TZ_landing_markirovka.md` (7 пунктов): мобильный первый экран, `tel:`-звонок, доставка заявки в email и MAX за 1–2 минуты, валидация пустых полей, плавающая кнопка, цель в Метрике, инструкция заказчику по подсчёту заявок. Прогонять перед показом заказчику и перед публикацией.

### 5. Целостность контента

- телефоны, email, режим работы, адрес — совпадают с приложением А ТЗ посимвольно;
- все фото существуют по указанным путям, у изображений заполнены alt;
- ссылка на политику ПДн открывается, чекбокс согласия обязателен;
- антиспам-проверка формы работает.

## Правила

- Стек намеренно vanilla — **не добавлять** фреймворки, сборщики, package.json, npm-зависимости без явного указания пользователя.
- Правки — только по ТЗ; инициативные улучшения предлагать отдельно, не делать молча.
- Тестовые данные для формы — заглушки, не реальные номера.
- Язык интерфейса и контента — русский. Мета-теги — русские.
- Не отправлять данные наружу без разрешения (фиды заявок, контакты заказчика).
- Результат работы: список изменённых файлов + краткий отчёт, без пересказа того же самого.
