# CLAUDE.md

Этот файл — инструкция для Claude Code при работе в этой папке.

## Проект

Одностраничный лендинг для ООО «Технические решения логистики» (ООО «ТРЛ», Казань) — услуги маркировки товаров «Честный знак» на собственном таможенном складе (включая алкогольную продукцию по лицензии РАР).

Статус на 2026-09-25: стадия ТЗ/КП. Кода лендинга пока нет; когда появится — статический vanilla HTML/CSS/JS в этой же папке, без сборки и зависимостей.

## Главные источники требований

- `TZ_landing_markirovka.md` — ТЗ v1.3: требования, критерии приёмки, ограничения, приложение А (контакты и текст FAQ от заказчика). **Любая правка лендинга сверяется с ним.**
- `KP_landing_markirovka.md` (+ `.pdf`) — коммерческое предложение: этапы, цена, бюджет Яндекс Директа.
- `запрос клиента.md`, `Письмо клиенту.md` — исходный запрос и переписка.
- `Прогноз_бюджета_Директ.md`, `forecast.4763.xls` — прогноз бюджета Яндекс Директа (≈13 600 ₽/мес, регион — вся Россия).
- `Материалы заказчика/` — 7 фото склада (`Фото склада/`), карточка реквизитов ООО «ТРЛ».
- `kp_print.css` — стили печати PDF-версии КП.

## Скиллы проекта

- `tz-kp-from-client-request` — превращение запроса клиента в ТЗ и КП (уже использован; пригодится при новых запросах).
- `trl-landing` — разработка, наполнение и проверка самого лендинга: структура, локальный запуск, QA, критерии приёмки из ТЗ.

## Как работаем

- Сначала план — потом действие.
- Правки лендинга — только по ТЗ; расхождение между «хочется улучшить» и ТЗ фиксировать как вопрос, а не делать молча.
- Тестирование формы и заявок — на тестовых данных (имена/телефоны-заглушки), не на реальных клиентах заказчика.
- Результат: список изменённых файлов + краткий отчёт о сделанном.

## Чего не делать

Без разрешения не:
- удалять файлы
- переименовывать файлы
- отправлять данные куда-либо (в т.ч. реальные телефоны, email, реквизиты заказчика — наружу не передавать)
- выходить за пределы рабочей папки
- добавлять фреймворки, сборщики, package.json, npm-зависимости — стек намеренно vanilla

Без согласования с заказчиком не менять (зафиксировано в ТЗ):
- заголовок первого экрана «ТАМОЖЕННЫЙ СКЛАД В КАЗАНИ!» (формулировка и регистр — требование заказчика)
- порядок перечня услуг (алкоголь + лицензия РАР — первым)
- текст FAQ (12 вопросов-ответов, приложение А ТЗ)
- каналы приёма заявок — только email + MAX, без Telegram и WhatsApp

## Анти-паттерны

- Длинные предложения. Коротко и по делу.
- Фразы вроде «Конечно!», «Отличный вопрос!»
- Пересказ того, что только что сделано — достаточно списка файлов
- Пояснения очевидного
- Додумывание фактов о заказчике: если данные есть только в материалах заказчика — брать оттуда, а не изобретать

## Неопределённость

Если задача непонятна или есть несколько равных вариантов — уточнить перед действием, а не делать предположение.

## Правила нейминга файлов

Формула: `[дата — опционально] — [тема] — [тип].md`

Примеры:
- `2026-09-25 — статус этапа 1 — отчет.md`
- `инструкция-max-верификация.md`

## Формат ответа

Коротко. Структурировано. Без воды. Заголовки — только если ответ длиннее трёх строк.
